3 Firebase (השרת של הסנכרון וההתראות)

הכול בחינם בפועל. התוכנית "Blaze" דורשת כרטיס אשראי רק כי פונקציות ענן לא עובדות בלעדיה, אבל השימוש של שני משתמשים נמצא עמוק בתוך המכסה החינמית. בסוף יש הוראה להגדרת התראת תקציב ליתר ביטחון.

3.1 יצירת פרויקט

  1. היכנס ל-https://console.firebase.google.com/ עם חשבון הגוגל שלך.
  2. Create a project (או "Add project") ← שם: agala ← Continue.
  3. Google Analytics: כבה (Disable) ← Create project ← Continue.

3.2 שדרוג ל-Blaze

  1. בתפריט שמאלי למטה, ליד המילה Spark, לחץ Upgrade.
  2. בחר Blaze ← חבר כרטיס אשראי ← Purchase.
  3. אופציונלי אבל מומלץ – התראת תקציב: https://console.cloud.google.com/billing/budgets ← Create budget ← סכום 1$ ← Finish.

3.3 התחברות אנונימית

  1. בתפריט: Build ← Authentication ← Get started.
  2. לשונית Sign-in method ← Anonymous ← Enable ← Save.

3.4 מסד הנתונים

  1. Build ← Firestore Database ← Create database.
  2. Location: europe-west1 (Belgium) – חשוב שזה בדיוק המיקום הזה (הוא תואם לפונקציות). ← Next.
  3. בחר Start in production mode ← Create. (חוקי האבטחה האמיתיים יועלו בשלב 5.)

3.5 אפליקציית Android ← הקובץ google-services.json

  1. גלגל השיניים ליד "Project Overview" ← Project settings.
  2. למטה, "Your apps" ← סמל Android ← Package name: com.liad.agala (בדיוק כך) ← Register app.
  3. Download google-services.json ← העבר את הקובץ אל C:\Users\Liad Yaakobi\Desktop\AgalaApp\ (ליד config.xml).
  4. לחץ Next ... Continue to console (אין צורך בשאר הצעדים).

3.6 אפליקציית Web ← הקובץ firebase-web-config.txt

  1. באותו מסך Project settings ← "Add app" ← סמל </> (Web) ← כינוי: agala-web ← (בלי Hosting) ← Register app.
  2. יוצג בלוק const firebaseConfig = {…}. העתק אותו.
  3. פתח בפנקס רשימות את AgalaApp\firebase-web-config.txt, מחק את כל התוכן, הדבק את הבלוק, שמור וסגור.

5 הכנה, העלאת שרת ובניית APK

הרץ ב-cmd, בזה אחר זה (כל פקודה, ורק אחרי שהקודמת הסתיימה):

5.1 הכנה (שואלת שם משתמש ב-GitHub ושם repository)

cd /d "C:\Users\Liad Yaakobi\Desktop\AgalaApp"
npm run setup

יווצרו: מפתח חתימה לעדכונים, קובץ ההגדרות, ה-SDK של Firebase ועדכון חתום ראשוני. אם מופיעה שגיאה אדומה – היא כתובה בעברית ואומרת מה חסר.

5.2 העלאת חוקי אבטחה ופונקציות ענן

npx --yes firebase-tools@latest login
npm run deploy:firebase
  • הפקודה הראשונה פותחת דפדפן – היכנס עם אותו חשבון גוגל ואשר.
  • הפקודה השנייה עשויה לשאול אם להפעיל ממשקי API (Cloud Functions, Cloud Build, Eventarc, Scheduler…) – ענה Y.
  • בפעם הראשונה לעיתים מתקבלת שגיאת הרשאות Eventarc / Pub/Sub. זה תקין: המתן 3–5 דקות והרץ שוב את npm run deploy:firebase.
  • הצלחה נראית כך: Deploy complete!

5.3 העלאת הפרויקט ל-GitHub

החלף YOUR_USER בשם המשתמש שלך:

git init
git add -A
git commit -m "first version"
git branch -M main
git remote add origin https://github.com/YOUR_USER/agala-app.git
git push -u origin main

ייפתח חלון התחברות ל-GitHub בדפדפן (כמו באפליקציה הקודמת). לאחר מכן בדפדפן תראה בתוך ה-repository תיקייה update עם manifest.json ו-bundle.json.

5.4 הוספת Android והפלאגינים

npm run native

(מוריד את פלטפורמת Android ואת הפלאגינים: Firebase Messaging והפלאגין הייעודי של האפליקציה – גיבוי, קול והרשאות. לוקח כמה דקות.)

5.5 בניית ה-APK

npm run apk

בסיום: AgalaApp\agala-debug.apk. (בנייה ראשונה ארוכה, כמה דקות, כי Gradle מוריד תלויות.)

ה-APK הוא "debug" – מותקן ועובד רגיל. אם תרצה גרסת release חתומה: npm run apk:release (ייווצר keystore ב-keys; שמור ממנו גיבוי, כי בלעדיו אי אפשר לעדכן את האפליקציה על גבי הקיימת).

התקנה

אפשרות ב' – העברת הקובץ agala-debug.apk לטלפון (כבל USB, או שליחה לעצמך בוואטסאפ/דרייב), פתיחה ← "התקנה" ← אישור "התקנה ממקור לא ידוע" אם מבקש. לאמא אפשר לשלוח בוואטסאפ ולהנחות לפתוח את הקובץ.

אם בעתיד תבנה APK חדש ותקבל "האפליקציה לא הותקנה" – זה חתימה שונה; מחק את האפליקציה הקיימת והתקן מחדש (או השתמש בעדכון מ-GitHub, שלא דורש כלום).

10 אבטחה

  • אין סיסמאות: כל מכשיר מזוהה בהתחברות אנונימית, והגישה לרשימות מותנית בקוד החיבור (8 ספרות) שרק אתם מכירים. חוקי השרת (firestore.rules) מחייבים חברות בקבוצה לכל קריאה/כתיבה.
  • הרשימה האישית שלך נגישה רק למכשירים שנרשמו כ"ליעד".
  • אם הקוד דלף: "ניתוק והתחלה מחדש" אצלך ← יצירת חיבור חדש ← חיבור מחדש של אמא עם הקוד החדש.
  • תקשורת רק ב-HTTPS; גיבוי אוטומטי לענן של גוגל כבוי במניפסט (allowBackup=false).
  • עדכונים: חתומים בחתימה דיגיטלית (ECDSA P-256). המפתח הפרטי נשאר בתיקייה keys – שמור לו עותק (למשל בדרייב פרטי). בלעדיו לא תוכל לפרסם עדכונים עם אותו APK.
  • קובץ הגיבוי המקומי כולל את קוד החיבור, והוא בתיקיית Documents שאפליקציות עם הרשאת קבצים יכולות לקרוא. לא מומלץ לשתף אותו.

12 מה נבדק ומה לא (בכנות)

נבדק אצלי:
  • שכבת הממשק והלוגיקה בדפדפן (32 בדיקות): יצירת חיבור, קוד שגוי/נכון, הוספה/כפילות/כמות/מחיקה וביטול, הכתבה, שליחה, עדכון אחרי שליחה, "הוזמן", רשימה אישית, הרשאות (אמא לא יכולה לקרוא את הרשימה שלך), הגדרות, מראה, גיבוי ושחזור, התראות בחזית, מצב ללא אינטרנט.
  • עדכונים חתומים: חתימה פגומה נדחית, חתימה תקינה מותקנת, חבילה מתרסקת מוחלפת אוטומטית בגרסה היציבה.
  • פונקציות הענן (10 בדיקות): אזור זמן ישראל כולל חורף/קיץ, חלון תזכורת, "פעם ביום", דילוג אם כבר שלחה, ניקוי טוקנים מתים.
  • קוד ה-Java של הפלאגין עובר קומפילציה מול הגדרות API שכתבתי (בדיקת תחביר וטיפוסים).
לא נבדק (אין לי Android SDK, אינטרנט ל-Maven/Firebase, או מכשיר בסביבה שלי):
  • בניית ה-APK בפועל, והרצה על מכשיר אמיתי.
  • שליחת התראות אמיתיות דרך FCM, וחוקי האבטחה של Firestore מול Firebase אמיתי (בדקתי את הלוגיקה שלהם מול סימולטור, לא מול ה-emulator של גוגל).
  • התנהגות סוללה של יצרנים (סמסונג וכו') – לכן יש בדיקת "הרצה ברקע" וגיבוי משלים.
לכן: בנייה ראשונה עלולה להציג שגיאה בגלל הבדלי גרסאות. זה צפוי; שלח לי את הטקסט של השגיאה ואתקן מיד.
